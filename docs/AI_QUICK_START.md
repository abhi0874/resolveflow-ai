# Run and verify ResolveFlow AI

Use a fresh clone of [public main](https://github.com/abhi0874/resolveflow-ai), inspect `git status --short --branch`, and read [release status](PROJECT_STATUS.md). Model files, credentials and private databases are deliberately excluded. A developer's current sessions or recovery keys must never be copied to another assistant.

1. Install Node per `.nvmrc` and Python per `apps/api/.python-version`. Run `npm ci` in `apps/web` and `uv sync --locked` in `apps/api`. For the public experience alone, run `npm run demo:dev` in the web directory and open the printed loopback URL.
2. For the full application, provision a new **local** PostgreSQL database with pgvector and a private Valkey instance. Follow the [database](DATABASE.md) and [worker](WORKER_OPERATIONS.md) procedures for the supported platform. Set a private `DATABASE_URL` and `RESOLVEFLOW_REDIS_URL`. On the owned new database, run `uv run --locked alembic upgrade head` and `uv run --locked python scripts/workflows.py setup` from the API directory. For an existing database, establish its identity and verify a recoverable backup before considering any migration.
3. Configure private storage and preserved ML artifacts as described in [classifier](ML_CLASSIFICATION.md) and [retrieval](SEMANTIC_SEARCH.md) documentation. Enable the fixture AI provider and leave live inference disabled. Configure loopback mail delivery through [Mailpit](EMAIL_DELIVERY.md). Google is optional; see [sign-in settings](GOOGLE_SIGN_IN.md). Sign-in alone never verifies external email delivery.
4. To exercise deletion on a new disposable installation, set `RESOLVEFLOW_ERASURE_JOURNAL_ROOT` and `RESOLVEFLOW_ERASURE_WITNESS_ROOT` to distinct, empty owner-only directories and follow the [initialization and retention procedure](BACKUP_OPERATIONS.md#account-deletion-recovery). Use private independent storage and custody for recovery outside a disposable rehearsal.
5. From the API directory start `uv run --locked uvicorn resolveflow.main:app --app-dir src --host 127.0.0.1 --port 8000`. In separate terminals start `uv run --locked python scripts/jobs.py dispatch` and `uv run --locked python scripts/jobs.py worker`. Start the web app with `NEXT_PUBLIC_APP_MODE=full API_INTERNAL_URL=http://127.0.0.1:8000 npm run dev` from `apps/web`. Match `RESOLVEFLOW_TRUSTED_ORIGINS` and mail public origin to the actual loopback browser origin.
6. For tests, use a fresh synthetic database cluster. See `apps/api/tests/conftest.py` for `TEST_DATABASE_ADMIN_URL` and `--run-db`. In `apps/api`, run `uv run --locked ruff check .` and `uv run --locked ruff format --check .`. In `apps/web`, run `npm run lint`, `npm run typecheck`, and build the mode under test. Run `npm run demo:build && npm run test:demo` for the synthetic showcase. With a full-mode build and the local PostgreSQL/Valkey/Mailpit test prerequisites installed, run `uv run --locked python scripts/test_browser.py --google-oidc auth.spec.ts identity-email.spec.ts google-auth.spec.ts account-settings.spec.ts account-erasure.spec.ts` from the API directory. Configure the browser channel required by Playwright.

The [staging templates](../deploy/staging) enumerate server-only variable names for private origin, email, Google and storage. They are reference material for a future separately approved host. Running the portfolio requires no paid service. See [hosting limits](ZERO_COST_HOSTING.md).
