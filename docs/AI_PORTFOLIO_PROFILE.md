# ResolveFlow AI | Master portfolio profile

**ResolveFlow AI is a support-agent workspace that turns a ticket into a reviewable answer.** It brings together a trained ticket classifier, search over private support documents, source-grounded drafting and a durable human approval step. Its intended users are support agents who need evidence for a reply, workspace leads who review decisions, and engineers evaluating how ML behaves inside a real application. The portfolio objective was to make each recommendation inspectable and recoverable, including when the system should withhold one.

**Public entry points:** [GitHub repository](https://github.com/abhi0874/resolveflow-ai) · [Live showcase](https://resolveflow-ai-showcase.vercel.app/) · [Interactive workspace](https://resolveflow-ai-showcase.vercel.app/demo) · [Engineering walkthrough](https://resolveflow-ai-showcase.vercel.app/demo/architecture).

## What a recruiter can try

Open the inbox and select the synthetic refund request. Follow its workflow to the policy passage, replay the stages, inspect the proposed answer and record a decision on that exact draft. Try the insufficient-evidence example to see why approval can be unavailable. Search the knowledge library, add a synthetic ticket, inspect the resulting analytics and reset the session. Keyword search, navigation, edits, charts and decisions work in the browser. The tickets, classifications, source matches and generated answers in this demonstration are authored or precomputed.

## Follow one ticket through the local application

1. An authenticated user opens a workspace and creates or edits a ticket. Next.js forwards allowed full-mode requests to FastAPI. The API checks the session, origin, CSRF protection where required, workspace membership and action permissions. Optimistic ticket versions prevent stale updates. [Ticket service](https://github.com/abhi0874/resolveflow-ai/blob/d2af3ec4ab99cba381ef30e91c2274284733f8ab/apps/api/src/resolveflow/services/tickets.py)
2. A classification request reads the stored title and description. The classifier returns a predicted category, score, model version and optional suggestion. The user can accept through a separate version-checked ticket update. Priority uses explicit rules and remains a recommendation. [Inference](https://github.com/abhi0874/resolveflow-ai/blob/d2af3ec4ab99cba381ef30e91c2274284733f8ab/apps/api/src/resolveflow/ml/classifier.py) · [Priority rules](https://github.com/abhi0874/resolveflow-ai/blob/d2af3ec4ab99cba381ef30e91c2274284733f8ab/apps/api/src/resolveflow/workflows/priority.py)
3. Authorized staff ingest PDF, Markdown or text documents. Bounded extraction produces deterministic chunks. Indexing records the embedding space and content hash for each chunk. Search embeds a query and returns ranked passages from accessible, indexed material in the same workspace. [Documents](https://github.com/abhi0874/resolveflow-ai/tree/d2af3ec4ab99cba381ef30e91c2274284733f8ab/apps/api/src/resolveflow/documents) · [Retrieval service](https://github.com/abhi0874/resolveflow-ai/blob/d2af3ec4ab99cba381ef30e91c2274284733f8ab/apps/api/src/resolveflow/retrieval/service.py)
4. Starting a workflow persists execution and job state in PostgreSQL. A dispatcher publishes work through RQ/Valkey. A Python worker loads the execution and runs seven logical stages in order: classification, priority, retrieval, context, generation, verification and approval. A conditional edge terminates failed or cancelled runs. These stages are functions in one graph, rather than seven independently hosted agents. [Graph](https://github.com/abhi0874/resolveflow-ai/blob/d2af3ec4ab99cba381ef30e91c2274284733f8ab/apps/api/src/resolveflow/workflows/graph.py) · [Stage contracts](https://github.com/abhi0874/resolveflow-ai/blob/d2af3ec4ab99cba381ef30e91c2274284733f8ab/apps/api/src/resolveflow/workflows/contracts.py) · [Dispatch](https://github.com/abhi0874/resolveflow-ai/blob/d2af3ec4ab99cba381ef30e91c2274284733f8ab/apps/api/src/resolveflow/jobs/dispatch.py)
5. LangGraph checkpoints progress in PostgreSQL and can interrupt at human review. The reviewer inspects source quotations and approves, rejects or requests revision. Review is tied to the draft, ticket version and source validity. Resume checks authorization again. The recorded decision is internal. The application has no customer-send, refund or account-change action. [Workers](https://github.com/abhi0874/resolveflow-ai/blob/d2af3ec4ab99cba381ef30e91c2274284733f8ab/apps/api/src/resolveflow/workflows/workers.py) · [Checkpoint storage](https://github.com/abhi0874/resolveflow-ai/blob/d2af3ec4ab99cba381ef30e91c2274284733f8ab/apps/api/src/resolveflow/workflows/storage.py) · [Draft service](https://github.com/abhi0874/resolveflow-ai/blob/d2af3ec4ab99cba381ef30e91c2274284733f8ab/apps/api/src/resolveflow/rag/service.py)

## Classification and model selection

**Default model.** The seven labels are Account Access, Billing, General Support, Other, Product Inquiry, Subscription Management and Technical Support. Input processing validates the title and description, normalizes Unicode NFC, collapses whitespace and joins the fields. V1 uses word unigram/bigram TF-IDF with sublinear term frequency, L2 normalization and up to 12,000 features, followed by logistic regression (LBFGS, C=4, seed 42). Vocabulary and coefficients are learned on the training split. The original corpus contains 280 synthetic tickets, 40 per class, in 140 related scenario pairs. The grouped split is 168 train, 56 validation, 56 test. The active default, `baseline-v1`, scored **44/56 (78.57%) accuracy and 0.7846 macro-F1** on that original held-out test. [Training](https://github.com/abhi0874/resolveflow-ai/blob/d2af3ec4ab99cba381ef30e91c2274284733f8ab/apps/api/src/resolveflow/ml/training.py) · [Model specification](https://github.com/abhi0874/resolveflow-ai/blob/d2af3ec4ab99cba381ef30e91c2274284733f8ab/docs/ML_CLASSIFICATION.md) · [Baseline evaluation](https://github.com/abhi0874/resolveflow-ai/blob/d2af3ec4ab99cba381ef30e91c2274284733f8ab/docs/evaluation/classifier-v1-evaluation.json)

**Decision contract.** The highest probability gives the predicted class. Empty lexical features or a score below 0.45 suppress the actionable suggestion. An uncalibrated score is not a probability guarantee. “Other” is a learned category, separate from abstention. The service loads versioned data-only JSON and validates dimensions, classes and numeric values before use. No request trains a model. [Artifact code](https://github.com/abhi0874/resolveflow-ai/blob/d2af3ec4ab99cba381ef30e91c2274284733f8ab/apps/api/src/resolveflow/ml/artifact.py) · [Inference contract](https://github.com/abhi0874/resolveflow-ai/blob/d2af3ec4ab99cba381ef30e91c2274284733f8ab/apps/api/src/resolveflow/ml/contracts.py)

## Semantic retrieval and grounded generation

The local encoder is Sentence Transformers’ English-oriented all-MiniLM-L6-v2, pinned to revision `1110a243fdf4706b3f48f1d95db1a4f5529b4d41`. It loads verified files offline. Long chunks use 254-token windows with 32-token overlap, then mean aggregation and L2 normalization. PostgreSQL stores 384-dimensional vectors with workspace, document, chunk, model-space and content identity. Exact cosine ranking over eligible rows gives predictable results on the small local corpus. Each result can be traced back to a passage. Approximate indexing at scale remains unevaluated. [Encoder](https://github.com/abhi0874/resolveflow-ai/blob/d2af3ec4ab99cba381ef30e91c2274284733f8ab/apps/api/src/resolveflow/retrieval/provider.py) · [SQL query](https://github.com/abhi0874/resolveflow-ai/blob/d2af3ec4ab99cba381ef30e91c2274284733f8ab/apps/api/src/resolveflow/retrieval/service.py) · [Indexing design](https://github.com/abhi0874/resolveflow-ai/blob/d2af3ec4ab99cba381ef30e91c2274284733f8ab/docs/SEMANTIC_SEARCH.md)

Both methods ranked the same 14 fictional documents (14 chunks) against 24 labeled questions, with the same relevance labels and rank cutoffs. Semantic search used a preselected cosine similarity floor of 0.30. The keyword baseline used word TF-IDF with English stop-word removal and kept positive scores. These are results for the two configured systems.

|---|---:|---:|

Hit@1 differed by **38.10 percentage points**. Recall is averaged per question, and MRR averages the reciprocal rank of the first relevant result, counting misses as zero. Separately, 0/3 unsupported queries returned results with semantic search and 2/3 with keyword TF-IDF. The semantic benchmark recorded **7.90 ms median and 8.52 ms p95** for 24 local in-process HTTP searches that included auth, query encoding and database lookup. The hosted library uses browser keyword filtering. [Frozen corpus](https://github.com/abhi0874/resolveflow-ai/blob/d2af3ec4ab99cba381ef30e91c2274284733f8ab/data/synthetic/retrieval-v1/corpus.json) · [Benchmark method](https://github.com/abhi0874/resolveflow-ai/blob/d2af3ec4ab99cba381ef30e91c2274284733f8ab/apps/api/tests/test_retrieval_evaluation.py) · [Saved results](https://github.com/abhi0874/resolveflow-ai/blob/d2af3ec4ab99cba381ef30e91c2274284733f8ab/docs/evaluation/retrieval-v1.json)

The generator receives a bounded ticket and up to four passages with at most 6,000 context characters by default. The prompt separates untrusted content from instructions. An AIProvider adapter requests JSON matching a Pydantic schema. Supported statements must identify a supplied chunk and quote text actually present there. Review checks stored content hashes and draft identity again. Insufficient evidence can produce a local abstention before a provider call. A valid quote establishes provenance. Semantic entailment and completeness require separate evaluation. [Prompt and validation](https://github.com/abhi0874/resolveflow-ai/blob/d2af3ec4ab99cba381ef30e91c2274284733f8ab/apps/api/src/resolveflow/rag/prompt.py) · [Gemini adapter](https://github.com/abhi0874/resolveflow-ai/blob/d2af3ec4ab99cba381ef30e91c2274284733f8ab/apps/api/src/resolveflow/ai/providers.py) · [Review service](https://github.com/abhi0874/resolveflow-ai/blob/d2af3ec4ab99cba381ef30e91c2274284733f8ab/apps/api/src/resolveflow/rag/service.py)

The configurable provider defaults to `gemini-3.6-flash`, minimal thinking, 1,024 maximum output tokens, a 25-second timeout, one call and zero retries. Saved local live inference is disabled. Current provider availability and billing eligibility are unverified. A single authorized synthetic smoke passed structured output and citation checks after an earlier invalid-output attempt. Its one provider call took 3,171.57 ms. The hosted generation route returns a disabled response without contacting Gemini. ## Reliability decisions and verification boundaries

- **Retries and restarts.** The PostgreSQL outbox records intent before broker publication. Persisted job identity, bounded attempts, checkpoint state and draft reuse let workers reconcile interrupted work. Repeated request IDs are scoped to the requester and workspace, and recovery can reuse an already persisted completed draft. Authorization and draft validity are checked when work resumes. Historical isolated tests cover broker restart after queuing resume, with the same draft ID, and worker interruption with one surviving draft and activity record. Delivery is at least once. [Recovery tests](https://github.com/abhi0874/resolveflow-ai/blob/d2af3ec4ab99cba381ef30e91c2274284733f8ab/apps/api/tests/test_jobs.py) · [Step 20 results](evaluation/PUBLIC_EVIDENCE.md#recorded-workflow-backup-and-release-checks) · [Job service](https://github.com/abhi0874/resolveflow-ai/blob/d2af3ec4ab99cba381ef30e91c2274284733f8ab/apps/api/src/resolveflow/jobs/service.py) · [Worker](https://github.com/abhi0874/resolveflow-ai/blob/d2af3ec4ab99cba381ef30e91c2274284733f8ab/apps/api/src/resolveflow/jobs/worker.py) · [Operations](https://github.com/abhi0874/resolveflow-ai/blob/d2af3ec4ab99cba381ef30e91c2274284733f8ab/docs/WORKER_OPERATIONS.md)
- **Tenant access and change control.** Workspace checks scope tickets, documents, retrieval candidates, job execution and analytics. A changed ticket or source can invalidate a prior review. Viewers cannot retrieve private evidence merely by knowing a document ID. Local recovery uses encrypted restic snapshots and isolated restores. One rehearsal matched 24 table fingerprints at migration 0012. Independent key custody and off-host recovery remain open. [Authorization](https://github.com/abhi0874/resolveflow-ai/blob/d2af3ec4ab99cba381ef30e91c2274284733f8ab/docs/AUTHENTICATION.md) · [Recorded verification summary](evaluation/PUBLIC_EVIDENCE.md#recorded-workflow-backup-and-release-checks)
- **Release evidence.** Step 20 recorded 317 backend, 29 full-application browser and 16 demo tests. The later showcase release separately recorded 29 local checks, then 23 hosted browser/API scenarios plus one local font/source check, all passing. Counts describe distinct snapshots. The production build, TypeScript and ESLint passed for the redesign. These results are summarized with their scope in the public evidence file.
